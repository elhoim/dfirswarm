### Added: the reverse-engineering pack reads document and PE structure, and runs capa and FLOSS when they are installed

Phase 2 of the pack review, the tools. Nothing is executed and nothing is verified: each tool reads bytes through checked ranges, under budgets, and says what it read and what it did not.

- **doc_structure** reads what `doc_probe`'s byte search cannot (stdlib only). An OLE compound file: the header, FAT and mini FAT, the whole directory (every entry, the ones no storage reaches marked `reachable: false`, each stream's chain checked against the file), the VBA project (the `dir` stream is decompressed, each module's stream and the size of its compressed and decompressed source are listed; source is written out only with `extract: ["vba"]`, byte for byte, or not at all when it passes a budget), and the encryption structures the Office formats record, read from the structure and not from a byte search: EncryptionInfo (standard and agile; scheme, algorithm, key size, hash and spin count), the Word FIB flags and table-stream header, the Excel FILEPASS record and BOUNDSHEET sheet kinds (an Excel 4.0 macro sheet, a very hidden sheet; after FILEPASS a sheet's name, visibility and kind are ciphertext, so only the count and each sheet's stream position are given), the PowerPoint Current User token. A name the Office formats give a stream is read only from a stream, a directory name of an odd length is a broken entry and not a decoding failure, and a VBA storage whose `dir` is missing or is not a stream is listed and said. OOXML: the central directory (part names compare case-insensitively, so two spellings of one part are a duplicate, said, and each copy of a part the tool reads is read), `[Content_Types].xml`, the document, workbook and presentation protection elements, and each `vbaProject.bin` read as a compound file. PDF: the cross-reference chain (tables, streams with a PNG predictor, hybrid files, every `/Prev` revision, a rebuild by scanning when the chain is unusable), every object's dictionary and stream filters, object streams, the encryption dictionary named by the current trailer, the catalog's actions with the key that reaches each (and those nothing reaches; no walker cuts a list, and in an encrypted file a target string is marked `ciphertext: true` and given by length), embedded files, and the page tree as two named numbers (the root's declared `/Count`, the leaves traversed) instead of a page count. RTF (also a file that begins with `{\rt`, as Word reads it): groups, nesting, control words counted by a tokenizer that honours `\binN`, object groups with their class, the hex length of their data, the signature it begins with (named, no byte printed) and the decoded OLE 1.0 object header (a payload that is a compound file is read as one), fields by the field type they begin with (when it is an ECMA-376 field type) and templates, by length, each a row of a table. A password verifier, salt, hash or encrypted key that a structure holds is reported by length and is in no answer and no file the answer names, and no key is tried (not even an empty password). A name, URL (its host included), string or path shaped like a token is withheld from the answer and from every table file, each row of which goes through the same withholding as the answer (the whole goes to the values file with `write_values`, in a job, and to a private names file). Every stream is read under budgets (a stream, all streams, an expansion ratio, entries, objects, nesting depth and the clock): each filter decodes in pieces and its output is held to the budget before it is allocated, the clock is checked inside a PDF parse, a read that failed at an offset or an object stream that failed is not read again, a budget or the clock reached anywhere is a limit with what was read kept, and the status is `partial`. An extracted object carries the sha256 of the bytes written.
- **pe_directories** reads the PE data directories `pe_info` declares and does not read: every export (ordinal as base plus index, RVA, section, name through the ordinal table, forwarder), delay-load imports (the RVA form and the old virtual-address form), the TLS directory with each callback and the section that holds it, the resource tree (type, name, language, size, file offset; `extract: ["resource:<row>"]` writes a row exactly), the version information and the manifest's requested execution level, the CLR header and the metadata root's version string and streams (the metadata tables are not read, so there is no assembly name), the debug directory with the CodeView GUID, age and PDB path (with a REPRO entry no stamp is rendered as a time), and the Rich header's raw entries. Each delay-load name table is read once, so descriptors that share one do not multiply its rows; a section is read from its PointerToRawData rounded down to 512 bytes, as the loader maps it; every bound that is reached is a limit. An export, a callback, a strong-name flag or a PDB path is reported as a declaration or a claim.
- **capa-floss**, a recipe that is not run automatically: for a PE or ELF it runs `capa -j` and `floss -j` if they are installed, each in the recipe's own process group with its output going straight to a file, and keeps the whole JSON, stderr, argv, what `--version` printed and the exit code of each. An engine that is not installed, cannot be executed, exits non-zero, is stopped at its time limit or prints something unreadable (for FLOSS: no `strings` mapping of the kinds the recipe reads) is a named status of that engine, and the recipe is `partial` or `failed`, never `complete`. capa's rule set (`meta.analysis.rules`) and FLOSS's `enable_*` flags are recorded. A second run into the same directory writes its receipt under new names and leaves the earlier `coverage.json` and `index.tsv` as they were. `matches.tsv` lists capa's matched rules (name, namespace, ATT&CK ids, count); no string and no matched feature is copied into the receipt, the index or that table. capa and FLOSS are not installed where the tests run, so the suite uses stand-ins that print the JSON shape the recipe reads or fail in one named way; it says so, and holds only the recipe's own contract. The `--version` and `-j` arguments are the recipe's assumption about both programs: a program that rejects one fails visibly with its stderr kept.

Fixtures are built from the format specifications and not from the tools' output ([MS-CFB], [MS-OVBA] with a compressor that writes literal tokens and a hand-made copy token, [MS-OFFCRYPTO], [MS-DOC], [MS-XLS], [MS-PPT], ISO 32000, the RTF specification, [MS-OLEDS], the PE/COFF specification). Hostile cases are named tests, among them one per finding of the review (an ASCII85 `z` object stream, a filter chain past its ratio, an unterminated object referenced six times, an object stream that fails after a predictor, five million empty cross-reference subsections, a canary in every printable place of each format, case-variant part names, actions past every old slice, a trailer inside a stream, a deleted object an older hybrid stream defines, 2,000 delay-load descriptors sharing one table; a looping FAT chain, a directory tree that returns to itself, a cut file, a decompression bomb in a VBA module, a PDF stream and an object stream, a `/Prev` loop, a four-billion-entry cross-reference subsection, 5,000 nested arrays, 30 million open braces against a one-second clock, 50,000 exports). The shared withholding block of `doc_structure`, `pe_directories` and the `capa-floss` recipe is held equal to the network pack's text, and the recipe's process block to the one `fuzzy_hash` and `static-binary` carry.

### Changed: the reverse-engineering pack's skills point at the new readers, and its requirements say what is unpinned

`documents/macros`, `documents/external-and-active-content`, `pe/structure` and `pe/signature-and-resources` name `doc_structure` and `pe_directories` where they said the pack had no reader for OLE directories, PDF and RTF structure, exports or resources. `requires/host.json` marks the programs that are not pinned (FLOSS, oletools, YARA, strings, ssdeep, tlsh, and the Homebrew install of capa) as unpinned (declared, unverified); no program was added and no pin was invented. The pack README describes both tools and the second recipe. Pack reverse-engineering.
