### Added: the reverse-engineering pack reads document and PE structure, and runs capa and FLOSS when they are installed

Phase 2 of the pack review, the tools. Nothing is executed and nothing is verified: each tool reads bytes through checked ranges, under budgets, and says what it read and what it did not.

- **doc_structure** reads what `doc_probe`'s byte search cannot (stdlib only). An OLE compound file: the header, FAT and mini FAT, the whole directory (every entry, the ones no storage reaches marked `reachable: false`, each stream's chain checked against the file), the VBA project (the `dir` stream is decompressed, each module's stream and the size of its compressed and decompressed source are listed; source is written out only with `extract: ["vba"]`, byte for byte, or not at all when it passes a budget), and the encryption structures the Office formats record, read from the structure and not from a byte search: EncryptionInfo (standard and agile; scheme, algorithm, key size, hash and spin count), the Word FIB flags and table-stream header, the Excel FILEPASS record and BOUNDSHEET sheet kinds (an Excel 4.0 macro sheet, a very hidden sheet), the PowerPoint Current User token. OOXML: the central directory, `[Content_Types].xml`, the document, workbook and presentation protection elements, and each `vbaProject.bin` read as a compound file. PDF: the cross-reference chain (tables, streams with a PNG predictor, hybrid files, every `/Prev` revision, a rebuild by scanning when the chain is unusable), every object's dictionary and stream filters, object streams, the encryption dictionary named by the current trailer, the catalog's actions with the key that reaches each (and those nothing reaches), embedded files, and the page tree as two named numbers (the root's declared `/Count`, the leaves traversed) instead of a page count. RTF: groups, nesting, control words counted by a tokenizer that honours `\binN`, object groups with their class, the hex length of their data and the decoded OLE 1.0 object header (a payload that is a compound file is read as one), fields and templates by their first word and length. A password verifier, salt, hash or encrypted key that a structure holds is reported by length and is in no answer and no file the answer names, and no key is tried (not even an empty password). A name, URL, string or path shaped like a token is withheld from the answer and from every table file (the whole goes to the values file with `write_values`, in a job, and to a private names file). Every stream is read under budgets (a stream, all streams, an expansion ratio, entries, objects, nesting depth and the clock); a budget that is reached is a limit and the status is `partial`.
- **pe_directories** reads the PE data directories `pe_info` declares and does not read: every export (ordinal as base plus index, RVA, section, name through the ordinal table, forwarder), delay-load imports (the RVA form and the old virtual-address form), the TLS directory with each callback and the section that holds it, the resource tree (type, name, language, size, file offset; `extract: ["resource:<row>"]` writes a row exactly), the version information and the manifest's requested execution level, the CLR header and the metadata root's version string and streams (the metadata tables are not read, so there is no assembly name), the debug directory with the CodeView GUID, age and PDB path, and the Rich header's raw entries. An export, a callback, a strong-name flag or a PDB path is reported as a declaration or a claim.
- **capa-floss**, a recipe that is not run automatically: for a PE or ELF it runs `capa -j` and `floss -j` if they are installed, each in the recipe's own process group with its output going straight to a file, and keeps the whole JSON, stderr, argv, what `--version` printed and the exit code of each. An engine that is not installed, exits non-zero, is stopped at its time limit or prints something unreadable is a named status of that engine, and the recipe is `partial` or `failed`, never `complete`. `matches.tsv` lists capa's matched rules (name, namespace, ATT&CK ids, count); no string and no matched feature is copied into the receipt, the index or that table. capa and FLOSS are not installed where the tests run, so the suite uses stand-ins that print the JSON shape the recipe reads or fail in one named way; it says so, and holds only the recipe's own contract. The `--version` and `-j` arguments are the recipe's assumption about both programs: a program that rejects one fails visibly with its stderr kept.

Fixtures are built from the format specifications and not from the tools' output ([MS-CFB], [MS-OVBA] with a compressor that writes literal tokens and a hand-made copy token, [MS-OFFCRYPTO], [MS-DOC], [MS-XLS], [MS-PPT], ISO 32000, the RTF specification, [MS-OLEDS], the PE/COFF specification). Hostile cases are named tests (a looping FAT chain, a directory tree that returns to itself, a cut file, a decompression bomb in a VBA module, a PDF stream and an object stream, a `/Prev` loop, a four-billion-entry cross-reference subsection, 5,000 nested arrays, 30 million open braces against a one-second clock, 50,000 exports). The shared withholding block of `doc_structure`, `pe_directories` and the `capa-floss` recipe is held equal to the network pack's text, and the recipe's process block to the one `fuzzy_hash` and `static-binary` carry.

### Changed: the reverse-engineering pack's skills point at the new readers, and its requirements say what is unpinned

`documents/macros`, `documents/external-and-active-content`, `pe/structure` and `pe/signature-and-resources` name `doc_structure` and `pe_directories` where they said the pack had no reader for OLE directories, PDF and RTF structure, exports or resources. `requires/host.json` marks the programs that are not pinned (FLOSS, oletools, YARA, strings, ssdeep, tlsh, and the Homebrew install of capa) as unpinned (declared, unverified); no program was added and no pin was invented. The pack README describes both tools and the second recipe. Pack reverse-engineering.
