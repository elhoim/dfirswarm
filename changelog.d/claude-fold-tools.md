### Added: five tools from two real runs join the tool library, each made general first

Two runs on one published case (an AD1 logical image, a 7 GB Windows memory image and a capture) forged tools as they went. The ones that are not tied to that case now live in `tool-library/`, which holds forty-six tools. Nothing of the case is left in them: what a run's copy knew (a flag's opening, a file, an offset, a limit) is a parameter, and each tool has a test that builds its own fixture and asserts what it says to a bad input as well as a good one.

- **`aes_schedule_scan`** finds AES-128 and AES-256 expanded key schedules in a file or memory image, at every byte alignment, in the standard byte order or with each 32-bit word reversed. **`aes_inverse_scan`** finds them as a decryption routine keeps them (InvMixColumns on the middle rounds, rounds in either order, either byte order), which `aeskeyfind` and the first tool do not see. Both check their tables against FIPS-197 before they read a byte, work a byte window under a time budget (`start`, `length`, `budget_seconds`, answering `complete: false` and `next_start`), never print a key (it goes to a private file in `out_dir`, by default `work/quarantine/<agent>/`, which a handover package leaves in the sandbox; the answer gives the offset, the layout and the key's sha256 for the ledger, and says what to do about a key file kept anywhere else) and say that a hit is a lead.
- **`encoded_literal_scan`** finds a literal whose start and end the caller knows (`marker`, `closer`, `max_body`) in base64, base32, hex, rot13 and as UTF-16 or UTF-32 text, at every phase, decoding what it finds without running it, and reports only the literal, never what surrounds it. Its time budget and hit cap are kept between two hits, so a chunk full of them cannot hold a call past its time: it comes back partial with the `next_start` to go on from. It replaces three run tools that each had one case's flag format written in.
- **`marshal_inspect`** reads a Python marshal stream (a `.pyc`, or a stream carved from a packed program) as data: its constants and every code object with names, flags, constants and bytecode, for CPython 3.11 to 3.13. It never calls `marshal.loads` or builds a code object, bounds depth and counts, names a reference instead of following it, and says where a cut-short stream stopped.
- **`destlist_v4`** reads the DestList stream of a Windows jump list, version 4 (entry id, host name, last access, pin state, target path), reads a damaged stream as far as it goes, and refuses another version or the compound file around it by name.

`tests/tool-library-folded-runs.test.ts` holds the tests; `tool-library/README.md` says where each tool came from. The memory pack's key-schedule paragraph points at the two AES scanners.
