### Added: five more packs name a router, so the skills index of a run that carries them stays inside its budget

`windows-forensics` (`windows/router`), `linux-forensics` (`linux/router`), `memory-forensics` (`memory/router`), `macos-forensics` (`macos/router`) and `ransomware-response` (`ransomware/router`) each name one router (at most 400 tokens; 390, 379, 310, 304 and 329), the way `computer-forensics-base` does: when a run's index is over its 2,500-token budget the prompt shows the pack by that one line, and the router names every other skill of the pack exactly once by the question it answers. A router holds no rule and no tool: each note keeps its own, and every existing skill id is still a skill. `windows/router` carries a hint for the ids that do not explain themselves and the bare id for the rest, because 52 ids alone take 1,097 bytes of the 1,698 a router may have.

Before, 10 of the 40 combinations of the base pack with two others, and 87 of the 145 with three others, that hold one of the five packs had more than the run's 2,500 tokens of index entries and nothing to shorten them (the largest: the base pack with linux-forensics and windows-forensics, 3,554 tokens; with linux-forensics, memory-forensics and windows-forensics, 4,247), because none of the five had a router and a pack with none is shown whole. With the five routers and the shorter windows index none is over (the same two combinations are 2,758 and 3,474 tokens whole and 933 and 956 shown; with the base pack's own router, which is in #144, 69 and 92).

### Changed: the windows-forensics index fits the pack's 1,000-token budget

The 52 entries of `windows-forensics` were 1,807 tokens of index (the harness's count: the entry lines of `skills/INDEX.md`); with the router they are 989 of 1,000. The `title` and `when` lines of every skill are shorter and say the same: the trigger and the artefact, not a sentence. Nothing else in a skill changed: the bodies, the `Use when ... Not for ...` first lines, the tool and program lists are as they were. `linux-forensics` (881), `memory-forensics` (716), `macos-forensics` (619) and `ransomware-response` (663) were already within 1,000 and their entries are unchanged. Each pack's skills test now holds the router (one, within 400 tokens, no rule, every other skill named once, every old id alive), the pack index at 1,000 tokens as the harness counts it, and a render test that fails when the pack has no router: in a run over the budget the harness reports the pack as one it cannot shorten. Packs `windows-forensics`, `linux-forensics`, `memory-forensics`, `macos-forensics` and `ransomware-response`.

The `disk` profile (base, encrypted-containers, windows-forensics) was 3,058 tokens of entries before #144 and 3,156 with the base router; with the shorter windows index it is 2,240 (2,338 with the base router in), so it now fits the run's budget whole and no longer needs a router to be shown; the base pack's render test (`tests/pack-base-skills.test.ts`) that used it as its example now uses the base pack with encrypted-containers, windows-forensics and linux-forensics, with the other packs' routers left out of the count, and `docs/packs.md` says so.
