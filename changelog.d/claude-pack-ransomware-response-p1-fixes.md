### Fixed: encrypted_survey and ransom_note_scan follow the independent review of the ransomware-response pack

A review of the two tools on main found that `encrypted_survey` printed the identifier-bearing directories above a note (323 of 323 canaries, every shape), that the identifier shape missed whole classes, that `ransom_note_scan` wrote victim identifiers into an ordinary job's output, and that neither tool handled a stop signal, had a clock, or said `status`. Each fix below has a test that fails on the code it replaced (`tests/pack-ransomware-names.test.ts`, `-stop.test.ts`, `-status.test.ts`, and a case in `tests/secret-output-declaration.test.ts`).

- **One rule for every printed path.** Both tools carry the same `shown()` (a block held identical by a test): every component of every path they print is judged, the directories above a note, an unreadable directory, an exclusion and the root included, and the name of a file named like a note. `encrypted_survey` still prints the name of an encrypted file as it is: it is the evidence, and an identifier in it is printed. On 300 identifier-named directories above a note (hex, UUID, alphanumeric, decimal), `encrypted_survey` printed 300 and `ransom_note_scan` (whose rule judged each component but missed the decimal shape) 60; both print 0 now. `paths_withheld` counts a printed path once in both tools (the survey counted a file once, the scan every call).
- **The identifier shape is wider, and its rates are written down.** After NFKC folding a token of 8 or more letters and digits is identifier-shaped when it holds both, when it is 10 or more digits, or when it is letters only and is not one word, one capitalised word, several capitalised words or all capitals. Measured on random draws per shape (5,000 for the old rule, 20,000 for the new) as a directory name, printed before and after: 12 decimal digits 100% to 0, 20 decimal digits 100% to 0, 24 letters 100% to 0.03%, 12 full-width letters and digits 100% to 0.7%, a random 8-character letters-and-digits token 25.3% to 3.3% (9 characters 20.5% to 2.2%, 12 characters 12.3% to 0.6%, 16 characters 5.9% to 0.1%), base58 of 22 characters 2.2% to 0. Still printed whole: groups of four joined by a dash, an underscore or a dot, any token of 7 characters or fewer (100%), base32 of 16 characters (3.6%), 8 lower-case letters and digits (7.1%). The cost: on 600,000 real directory components of a developer machine's application, cache and package trees the rule withheld 4.9% (the old one 0.8%) and some component of 38% of their directories (the old one 7.6%), because dates, versions and package ids hold digits among letters. These figures are in both manifests. The network pack's shared withholding block is in both tools as well and is applied to every component (tokens, keys and user-info that are not identifier-shaped).
- **ransom_note_scan writes values only in a secret-output job.** The manifest declares `secret_output: {"when_args": ["write_values"]}` and the tool checks `SECRET_OUTPUT=1`, as `recovery_key_scan` does: a job that sets `write_values` is sealed as secret output, and one run by hand without the variable is refused with nothing written (before, `write_values` wrote a 0600 values file into an output sealed as ordinary).
- **Stop signals, a clock, temporary files.** SIGTERM, SIGINT and SIGHUP end each tool with one JSON answer (`status: failed`, `interrupted: true`, the signal, the coverage so far) and exit code 128 plus the signal (before: no output and -15, -2 or -1, and a traceback on SIGINT), after removing the census and pages it was writing (before, hidden temporary files of up to 6 MB stayed in the sealed output). A values file that `ransom_note_scan` had begun is kept, cut back to its last whole row, and the answer says how many rows it holds. `max_seconds` (default 780 for the survey and 480 for the scan, at most 840 and 540, under the manifests' 900 and 600) stops the walk, writes what was counted and answers `partial`, naming the entries and directories not examined; it was honoured within 2 seconds in the test. An unexpected failure removes the temporary files too and names no path.
- **A result file that is there is not replaced.** A rerun of `encrypted_survey` with other limits replaced the census (87,455 bytes) with a smaller one (64,960) and a candidates file (86,460) with a smaller one (63,876); the paging block of the windows pack now places every census and page without replacing: the same bytes keep their name, others take the next free `-2`, `-3`, and the answer names the file. `ransom_note_scan` pages the same way.
- **`status` and `status_basis` on every answer**, failures included (`failed`); `complete` stays beside them. `encrypted_survey` is `partial` also when candidates were left unprofiled by `sample` (before: `complete` with 79,800 of 80,000 unprofiled) and when an hour or extension table was capped (before: `complete`); with `census: false` the capped-table message no longer says the census has every file; a head or end window is compared with its threshold unrounded (a head of 7.4997 printed as 7.5 and was a candidate).
- Parser versions are `encrypted_survey/3` and `ransom_note_scan/3`. The skills `scope/triage-tools` and `encryptor/samples-and-notes` name `status`, `status_basis`, `max_seconds` and `sample`, and say the survey withholds identifier-shaped directories too.

Not done in this change, as the review lists them: `tail_hex` prints raw tail bytes of sampled candidates (a footer that holds an identifier is printed in hex; the skill says to run it as a job with `secret_output: true` where key material is expected); `groups` of a value and the `length` of an identifier candidate are derived quantities (the documented pattern); a dictionary attack on the digest of a short numeric-id note; the paging block still has several texts across packs; the census holds about 0.75 KB per file with no bound; the name rule's false positives (`help`, 0.1% of real names); a note value written with dashes does not withhold the digits-only name; a Cyrillic or CJK UTF-16 note without a byte-order mark is read as UTF-8; no test pins the goal's wording against "no hash of a secret". ransomware-response is re-sealed at 1.4.0.
