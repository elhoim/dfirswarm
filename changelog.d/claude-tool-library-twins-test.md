### Fixed: the tool-library copies of `check_inputs` and `icat_extract` are the pack's tools again, and one test holds every copy equal

`tool-library/check_inputs` (version 2) and `tool-library/icat_extract` (version 3) had drifted from the computer-forensics-base pack's tools (versions 4 and 8). A run started with `--tools-from tool-library` was offered the old ones: `check_inputs` that passed a size-only check, hashed in one read and wrote no receipt, and `icat_extract` that held the stream in memory, had no output or time budget, replaced an existing output file and defaulted to the image of one case. Both are now the pack's files, byte for byte, and the library README's rows say the new versions.

`tests/tool-library-twins.test.ts` finds every `tool-library/<name>` that is also `packs/*/tools/<name>` (21 today, 19 of them already equal) and fails unless the `run.*` files and `manifest.json` are byte-equal, the README row of each names the manifest's runtime and version, and no tool is in two packs. A difference can be declared in `tests/tool-library-twins-allowed.json` with its tool, file, reason and the digests of the two sides as they differ, so the test also fails when the difference is no longer the declared one or is gone; the list is empty and its ceiling in the test is zero. The test replaces the two narrower ones (six base tools, thirteen Windows tools). The library tests of `icat_extract` and `check_inputs` name an image and a 64-digit digest now, since the pack tools do not guess among several images or accept a short digest. A pack change to a tool that has a copy here has to update the copy in the same PR.
