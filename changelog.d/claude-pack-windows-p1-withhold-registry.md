### Security: regkv, shellbags and amcache_apps withhold names, paths and data by shape (windows-forensics)

`regkv`, `shellbags` and `amcache_apps` printed key names, value names and data, shell item names and Amcache paths and hashes whole whatever they held (100% for every shape in the review's canary harness), and `regkv` withheld only by value name and place. Stacked on the pull request that bounds their lists.

- **One boundary on every way out.** A shared `BOUNDARY` block (the owner-approved hybrid: an allow-list for identifier-shaped fields, a deny-list for free text, an independent backstop) judges every key and value of an answer, of an error answer, and of every row of every file the tool writes. A name, path, key or URL is shown as it is only when it fits a plain grammar (a path component by component; GUIDs, SIDs, addresses, 0x numbers, times and hexadecimal ids up to 24 digits are plain); free text has token-shaped runs, user-info, the value after a secret's name, vendor-prefixed tokens, padded base64 and PEM keys withheld, on a copy with invisible characters taken out; a second check, written apart from both, reads it back, and a string it replaces makes a complete answer `partial` and is listed under `boundary.replaced_at`. A withheld text is `<withheld N characters: reason>`.
- **Slots.** Registry key names and paths are keys, value names are keys (many are paths), value data is free text, binary data is hexadecimal (decoded and judged by its printable text), shell item names and Amcache paths are paths, Amcache hashes are digests. The existing name-and-place withholding of `regkv` (SAM, LSA secrets, `Password*` values) is unchanged and runs first. The names of a missing key's siblings are listed in the hive's order, no longer sorted by their text.
- `shellbags` matches `contains` against the shown path, and its result file names never depended on the needle.
- **`write_values: true`** writes the originals of everything withheld to `<tool>-values.jsonl` (mode 0600, created first, never replaced). It is accepted only in a job the harness runs as secret output: the manifest declares `secret_output: {"when_args": [...]}` and the tool checks `SECRET_OUTPUT=1`, and it is refused as JSON anywhere else before anything is made.
- **Measured** (the same grammar and rules as the owner-approved hybrid design, here as the shared `BOUNDARY` block): 1,000 random plants per shape and context, 175 cells. None printed whole: prefixed tokens (GitHub, GitLab, Stripe, SendGrid, Google, npm, AWS key ids), JWT, PEM keys, connection strings, user-info (also with an `@` in the password), NUL, zero-width and full-width splits, case-folded and glued prefixes, a token split across two fields. At most 2.2% whole: AWS-shaped, 16, 20 and 32-byte base64 keys (the worst cell is a letters-only key with a slash; 6% print a 12-character piece). Random base62 of 20 to 40 characters: at most 0.5%; random lower-case letters of 24: 9.4%; a 16-character base32 seed: 11%.
- **What it costs an examiner** (strings with any part withheld): 0 of 1,320 generated registry key paths, 5,200 file paths, 181 service names, 464 host names, 408 SIDs, 600 GUIDs and 1,200 typed digests; 2 of 109 registry value names (the 32-digit hash in a Chrome and an Edge autolaunch name); of 3,431 strings from real event logs (the EVTX attack-sample logs), 25: 17 of 1,040 whole event records, 7 of 313 command lines and messages, 1 of 322 path fields, all encoded PowerShell payloads, the 32-digit hash directories of the .NET native-image cache and similar.
- **Not recognised, by design, and asserted by a test so that the sentence stays true:** a plain password or passphrase, a pronounceable passphrase, a UUID-shaped key, a hexadecimal secret of up to 24 digits, anything under 16 characters in a name (75% to 100% of such plants are printed). Withholding is by shape; a file whose secrets matter is read in a job run with `secret_output: true`.
- `tests/pack-windows-forensics-boundary-registry.test.ts`: 300 random canaries of 14 shapes planted in a value's data, a value name, a key name, binary data, a shell item name and an Amcache path/publisher/value name (real regipy and the stand-in), the share printed whole asserted per family, the unclaimed shapes asserted to be printed, the backstop shown to replace the shapes it claims with the sanitiser removed, the values file and its refusals, and names and data an examiner must read shown unchanged.
- The block text is the same in every tool that carries it and in the tool-library twins, and is marked `SHARED BOUNDARY` so that the shared-block work can converge it with the other withholding blocks.

windows-forensics is re-sealed and raised by a patch version; the other withholding pull requests of this review also raise it, so the later ones need the merge-prep step.
