### Fixed: the memory-forensics tools stop by themselves, keep their secrets out of their answers and say what they did

`mem_carve` had no clock of its own: a hostile image (a signature every few bytes) wrote about 290 bytes of hit list per hit at some 270,000 hits a second, so the tool's 900 s limit was reached with no answer and tens of gigabytes on disk. It now stops at `max_seconds` (default 600, at most 780) or when the hit list reaches `max_results_bytes` (default 1 GiB), says `partial`, and gives `coverage.resume_start`, the offset to pass as `start` for the rest; every hit before it is reported and a test joins the two runs into the full hit list. A signal (SIGTERM, SIGINT, SIGHUP) ends all three tools with one JSON answer (`status: interrupted`, exit 128 plus the signal, no traceback); `mem_carve` names its partial hit list, `mem_fs` stops the engine and releases the mount first, and the engine now also ends with the tool on Linux.

Cutting slices out of an image (`extract_to`, which writes credential hives and browser databases among other things) now needs `write_values: true` and a job run as secret output; `mem_carve` and `mem_fs` declare `secret_output` for `write_values` in their manifests and check `SECRET_OUTPUT`, so the sentence "the tool cannot see whether the job was run with secret_output" is gone. Extracting credential hives stays deliberate, and a cracking tool downstream stays available; the slices go into a directory with mode 0700 as files with mode 0600. A slice is cut to the length its header declares where that is longer than the kind's fixed size (a Prefetch record up to 16 MiB, an event log file and a SQLite database up to 64 MiB), `cut_complete` says whether it holds the declared length, and `truncated` now means only that the file itself ends first (a real plain version-30 Prefetch record, longer than the old 128 KiB cut, was wrongly called truncated). A slice that was refused counts toward `max_extract`, so the earliest candidates are the ones tried. `results_to` is never replaced or written through a link: a name taken by a different file gives the next free one, and a link is refused. `limit` is clamped to 5000 and the answer says so.

`mem_fs`: a second export in the same job output adds its manifest rows (the manifest is appended to, not created exclusively) and counts the file it wrote, instead of leaving a file with no row and `contains_secret_values: false`; `timeout_seconds` is bounded to 2 to 480 so the call and the engine's stop stay inside 600 s; the output names write each unsafe character as `%XX` so two different names never share a file; the names the engine lists, and the first lines of its output in a failure, are judged before they are shown (a placeholder with the length for what they withhold, the plain names first and the changed ones after them in an order new every call), with the originals in a 0600 `names.jsonl` on `write_values` in a secret job; the engine's logs are 0600; a failure to start says what the host lacks in `blocked_by`; a lone surrogate or a name that is not UTF-8 no longer breaks a listing, a manifest or a paging file (the five `ensure_ascii=False` are gone); the counts add up to the paths requested. `mem_profile` prints `kernel_build` (now only the release, the first word after "Linux version ") and `version_user` only when they have the grammar of a version, and the banner is no longer printed; it samples once for every hint, stops at 200 s and names LiME ranges that overlap or are out of order. Every answer of the three tools carries `status` and `status_basis`.

Names are shown by shape (an allow-list per kind of field, the vendor prefixes of the shared withholding block, and an independent backstop that replaces a string it still finds secret-shaped and makes the answer `partial`): on 3,000 plants per shape in a name, none of the prefixed families, JWT, hex or user-info shapes was printed whole, and the share of base64 and base62 keys printed whole was 0.1 to 0.4 per cent; a plain password or a name under 16 characters is printed (a twelve-character password alone in a name is the stated residual), and about 3 per cent of the file names of a Mac are changed (hashes, hashed asset names). Pack memory-forensics.
