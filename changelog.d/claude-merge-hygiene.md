### Changed: branches that land together no longer conflict on the same lines

The last four pull requests conflicted with each other on the same few places every time: the one `package.json` line that listed every node suite, the top of `CHANGELOG.md`'s `[Unreleased]` section, the checksums and version of a pack two branches both changed, the kickoff goldens and the rule register, and the short help's line limit. Each cause is gone or handled by one step.

- **`npm test` finds its suites.** `scripts/test-node.ts` runs every `tests/**/*.test.ts` (the fixtures aside) but the ones `tests/node-tests.skip` names, each with its reason: the three VM suites `npm run test:vm` runs and the hand-run observation suite. A skip entry that names no suite fails the run. A new suite needs no edit anywhere.
- **Changelog fragments.** A pull request writes `changelog.d/<branch-slug>.md` instead of editing `CHANGELOG.md`. `scripts/changelog.ts --fold --release X.Y.Z` folds the fragments in, newest first by when each landed, and cuts the release; `--check` (run by `tests/changelog.test.ts`) holds their shape. `CHANGELOG.md` itself is unchanged.
- **One step to bring a branch up to date.** `scripts/merge-prep.sh`, run after `git merge origin/main`, resolves conflicts in generated files (a pack's `pack.json` merged key by key, its `skills/INDEX.md`, the kickoff goldens, `docs/rules.md`), seals every pack that differs from main, raises the patch version of a pack whose content differs from main's under the same version, writes the goldens and the rule register again and shows the diff. A hand-written key both sides changed, or a conflict in any other file, stops it, named. `tests/merge-prep.test.sh` makes two branches conflict in a scratch repository and checks each of these. CI's consistency checks are unchanged.
- **The short help may be 80 lines, not 60.** It was at 59: each branch that added a command passed alone and the merge of two failed, and commands were being packed onto one line to stay under the limit.
