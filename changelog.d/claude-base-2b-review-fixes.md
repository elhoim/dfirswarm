### Fixed: the computer-forensics-base skills follow the review of the split pass

A review of the Phase 2b skills of the base pack found three wrong rules, a set of smaller contradictions with the tools and the worker prompt, and content the split dropped. Each fix has a test in `tests/pack-base-skills.test.ts` that fails on the text it replaced.

- **A full search never shows an event did not happen.** `evidence/coverage` allowed the wording "X did not happen" on a search the harness found complete; it now says the phrase is never written (as `reporting/citations` and the worker prompt do): such a search answers whether X is in those sources, not whether the event occurred.
- **`archive_extract` runs with `secret_output` only when members may hold credential material.** `evidence/archives` told every extraction to run with it, which makes every downstream output sensitive and withheld from a redacted package (a triage archive is a whole case), and contradicted its own example. The flag is now conditional on what the member listing shows (credential stores, keys, tokens, browser profiles).
- **`data/sqlite` tells the agent how to keep values out of its context.** `sqlite_query` always returns at least one row of values in the inline page (`limit` is 1 or more) and a short BLOB as base64 and sha256, so on a secret table the skill says to select locators only (`rowid`, `length(col)`, `typeof(col)`). The tool is unchanged. The long-BLOB fields are named as the tool writes them (`blob_b64_head`, `head_bytes`), and `counts_agree` is described as a count of committed frames.
- **Smaller corrections.** `evidence/provenance` no longer lists a password store among the objects that get no digest (the file has one; a value read out of it does not) and says `archive_extract` writes a sha256 per member; `filesystem/encrypted` has the Sensitive output line for `bdeinfo`; `filesystem/semantics` agrees with the catalogue on a named stream (`name:stream` in a listing); `timeline/clocks` says a local time in a skipped hour does not exist (it points to a wrong zone, rule or clock) instead of keeping a reading for it; `filesystem/layers` uses `qemu-img info --backing-chain`; `data/documents-media` writes a re-saved copy under `{OUT}` only in a job; `evidence/tool-validation` says a second parser is a second reading only if it does not share the first's assumption; `evidence/scope` routes a lookup as `net_request` where the run has the dynamic network.
- **Content the split dropped is back**: the list of what a wrong header can mean (`filesystem/semantics`), the extension as only a claim (`filesystem/layers`), "not every timestamp on the volume" (`timeline/super`), the metadata's consistency check, the AFF4 and collection rows, the `img_stat` bound and the `target-query` readers (`filesystem/layers`), the LUKS header source (`filesystem/encrypted-metadata`) and the full list of what explains a creation later than modification (`timeline/clocks`).
- **Sizes.** Three leaves that carry restored content sit above 800 tokens as warnings (`filesystem/layers`, `data/sqlite`, `timeline/clocks`); none is near 1,000, no golden ceiling was raised, and the chains of the encrypted-containers skills that need `filesystem/encrypted` stay within their ceilings.
- **The seal case of `tests/skill-budgets.test.sh`** no longer passes without checking anything when the golden list names no leaf: it builds a pack with a leaf over 1,000 tokens and runs the seal assertions on it, and runs them on the first shipped pack the list names for a leaf as well when there is one.
