### Security: the network pack's tools stop printing object names, request URIs and credentials, and keep their output private

`pcap_extract` wrote every exported object's name into `index.tsv`, and ran tshark without `-q`, which (per its manual) prints a line for every packet, request URIs included, into the `_logs/*.stdout` it kept; `network_log_summary` copied every raw line, the request target and the text of each unparsed line into its tables; `zeek_run` returned records of every log inline, up to `limit` each (`password`, `cookie`, community strings, URL user-info among their fields); `suricata_run` wrote its EVE logs with whatever mode the process umask gave. All four now follow the secret-safe output pattern of `recovery_key_scan` (docs/packs.md, "Secrets and sensitive output") and withhold the same strings, by one block of code carried in each (`tests/pack-network-withholding.test.ts` holds the four copies equal): a name, a URL path segment or a message shaped like a token, a key, a JWT or a session id is withheld, a URL loses its user-info and every query value, and a byte that is not UTF-8 is written as `\xNN`, never raising. `pcap_extract` moves a token-shaped object name to `withheld-NNNNNN<ext>`, writes no digest of an object under 128 bytes, runs tshark with `-q` so no packet line is logged, and creates the output directory 0700 with every file 0600, tshark's own included; `network_log_summary` redacts the target and drops the `raw` column and the unparsed text from its tables; `zeek_run` withholds secret-named fields, URL user-info, token-shaped names, an FTP PASS argument and the hash of an object under 128 bytes from its inline records while keeping Zeek's own logs whole in a private directory; `suricata_run` runs with umask 077. `pcap_extract` and `network_log_summary` take `write_values: true` (refused outside a job, created exclusively, mode 0600, before anything runs; a second run in the same job is refused by name and leaves the first file) to write the real names, URIs and unparsed lines to one file under `$OUT`. The answers say `out_dir_contains_secret_values` and name `secret_output: true`.

### Fixed: the network pack's tools stop returning plausible wrong answers

- **`pcap_summary`** called a row of its table a session and every SYN-only packet a connection start; a tuple used again later merged with its earlier use, a SYN sent again counted twice, talkers summed captured bytes while conversations summed original bytes, only the first interface's link type reached the top level, block types other than three were skipped without a word, and a 96-byte snap length was declared content-free. The rows are now `tuple_conversations` or `endpoint_aggregates`; `syn_observations` and `syn_unique` (a SYN sent again with the same sequence number counted once); `bytes_original` and `bytes_captured` kept apart everywhere; an interface table and the pcapng interface statistics (the capturing interface's own drop counters); unsupported blocks counted by type; malformed options counted; truncation measured packet by packet instead of read off the snap length; the service port's basis stated (a SYN, a SYN/ACK, or a labelled guess); IPv6 host filters compared as addresses; times exact to the capture's own tick with the raw ticks beside them; aggregates spilled to SQLite past a cap; a cut-off or corrupt file refused with the packets read.
- **`beacon_score`** called a last interval over four times the median "stopped", though it ended in another event; sold a regularity ratio as "completeness" with a causal note; read a time with no zone as UTC; accepted NaN and infinite values; kept 40 intervals. It reports `long_final_gap` (a statement about silence after the last event only with `window_end` and `sensor_coverage_confirmed`, as a bounded negative), `event_density_ratio` without a cause, refuses a time with no zone unless `assume_utc` is given (and counts each), counts and names values that are not finite epoch seconds, counts duplicate times apart from distinct events, names its shapes descriptively (`tight_cluster` to `dispersed`; the cut-offs are conventions of the tool) and keeps every interval in a file.
- **`zeek_run`** ran `zeek -C -r <capture>` with no script while its note and the skill promised "a hash per reassembled object", always disabled checksum validation, ignored `#separator` and `#types`, dropped invalid JSON without a word and zipped mismatched columns into short records. It writes `network-forensics.local.zeek` (a `policies` list, default the file-hashing policy; a name Zeek resolves, never a path or a script from the evidence) and records its path and SHA-256, the Zeek version and the command; `checksum_validation` is a parameter; `hash_fields` and `hashes_produced` say whether `files.log` holds a hash at all; the reader follows the header (separators, `\xNN` escapes, sets, unset and empty, typed values, every time as raw text with a decoded `_utc`, JSON logs) and a record that does not fit is counted with its line and byte offset, kept whole in `malformed-<log>.jsonl`, and the run is not ok; requested-but-unwritten logs are kept apart from empty ones; `reporter`, `weird` and `capture_loss` are summarised every time.
- **`suricata_run`** addressed its TLS output through positional YAML paths (`outputs.1.eve-log.types.5...`) whose meaning depends on the installed configuration and named only the rules path in its answer. It writes an explicit `suricata.yaml` (or uses a `config` of the caller's, never one from `inputs/`), tests it with `suricata -T` before the run and runs nothing when that fails, records the version (`--build-info`, kept whole), the configuration's and the rules' SHA-256, the rule-line count and the checksum mode, reads Suricata's own rule-load numbers (a rule that failed to load fails the run), keeps what the configuration asks for, the TLS events logged and the JA3 and JA4 fingerprints produced as three numbers, and counts EVE lines that are not JSON, not objects or without an `event_type` with their line numbers. No Suricata default or version fact is stated.
- **`pcap_extract`** indexed an object by protocol, path, size and digest, so no object could be tied to a session; ran five 900-second passes under a 3600-second outer timeout and left no index when that fired; assumed `smb2` was an export type. It asks tshark for its version and export types (an unlisted explicit type is refused by name, the default list is cut to the listed ones), runs every pass under one deadline and kills the process group, and writes `index.tsv` and `receipt.json` before the first pass and after each. An HTTP object is tied to a frame by content (its SHA-256 against a streamed listing of responses, hashed as it goes by and never held or written): `matched_by_content`, `ambiguous` with the whole frame list in a file, or `unmapped` with the reason; a listing that fails or cannot be read whole claims nothing. A stop signal kills the pass and leaves a receipt that says `interrupted`.
- **`network_log_summary`** put three meanings in one `timestamp` column. The columns are `timestamp_raw`, `timestamp_utc` (only where the line gives enough to derive it: a web offset, Squid epoch seconds, an ISO firewall prefix with a zone; a syslog stamp is never read as UTC) and `timezone_source`, with `parse_status`, the line number and the byte offset and length of each line in the stream read. The file is read as bytes: substituted decoding and CRLF are counted, a line over `max_line_bytes` is located and not read, gzip expansion is capped, a cap or a corrupt gzip is a structured error that keeps the rows read and names the offset, and aggregates hold at most `max_distinct_values` per category with the overflow counted. The manifest names the three grammars implemented.
- **The `network-capture` recipe** judged `complete` from exit codes alone, wrote `coverage.json` only at the end, left `ipv6.src` and `ipv6.dst` out of the HTTP and TLS tables and called a selected-field projection "lossless". The receipt and `index.tsv` exist before the first step and are replaced after every step with each step's status, exit code, seconds and rows, the tool versions and a count of truncated packets; one deadline covers every step; HTTP/2 and QUIC tables are made only when `tshark -G fields` shows the installed build lists their fields; `http.tsv` is marked secret-bearing; the description says "complete listing of the selected fields".

### Changed: the network pack's tool manifests say what each tool reads and does not measure

Each manifest has a `use` (capture magic and extensions, log names), says what is and is not measured, names exactly the parameters its script reads (`tests/pack-network-manifests.test.ts` holds both to the script) and carries its raised version and the sha256 of its script. New suites (`tests/pack-network-*.test.ts`, 73 cases) build their captures from the pcap and pcapng layouts and their logs from the formats' own definitions, never from a tool's output, and stand in for tshark, Zeek and Suricata with programs that print what their documentation says they print: they prove each wrapper's logic and nothing about a real engine (whether a build lists an export type, applies `-Y` to an export, prints `http.file_data` for every body, loads a hashing policy by a given name or produces a JA4 fingerprint is for the build the evidence is read with). 66 of the 69 cases that exercise a changed tool fail on the tool as it was; the other three guard behaviour it kept. The skills, README and `requires` follow in the pack's next pull request.
