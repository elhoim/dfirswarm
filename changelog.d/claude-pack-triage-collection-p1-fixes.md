### Security: triage-collection tools print nothing evidence-derived unjudged

- `collection_id` printed the paths of collector logs found inside collected data and the level word of a Velociraptor `log.json` row (as a dictionary key) without the withholding; `collection_index` printed the directory of every KAPE copy log raw. A path shaped like an access key, a token or user-info in those places reached the answer. All three are withheld now, the level word is counted under its own word (`INFO`, `ERROR`, ...) or under `other`, and the copy-log lookup keeps the real directory private.
- Both tools now apply the withholding to every key and every value of the answer and of each table row at the point where it is serialised, so a field nobody listed is covered, and read the structure back with a second check written apart from the withholding (its own normaliser by Unicode category, named-secret scan, token prefixes, user-info scan, long digit runs, private-key markers and a measure of random-looking text). A string that check finds suspect is replaced by `<withheld: N bytes>`, counted in a `boundary` entry of the answer, and the answer is `partial`.
- New suite `tests/pack-triage-slots.test.ts` plants 200 random secrets of the listed shapes in every output slot of both tools (every kind of file, directory and link name, every CSV header and cell, every JSON key and value of uploads.json, results and log.json, every UAC line kind, every copy-log column, the arguments the tool echoes), in a job and not, with limit 1 and the default, and scans the answer, stderr, every file and every file name; it fails on the previous tools for three slots. The same trees are run with the withholding removed: the second check alone keeps every planted secret out of every channel.
- Both tool manifests are raised (collection_id 4, collection_index 5), the pack to 1.5.0.
