### Added: the computer-forensics-base pack extracts an archive's members under budgets, and never recreates a link (`archive_extract`)

The `archive-members` recipe has always said "extract a member with the archive's own program", and no pack shipped an extractor. `archive_extract` is that tool. It reads the format from the bytes (zip, tar plain or gzip, bzip2, xz, zstd, 7z, and a single gzip, bzip2, xz or zstd file, which is one member named by the gzip header or the archive's name), refuses RAR, CAB and OLE by name, and writes only member content: a symlink, hard link, device node or FIFO is a row with its target and `not_created`, never a file; a name that is absolute, has a drive letter or climbs with `..` extracts under an ASCII-safe rendering inside the output directory (`%2E%2E`, `%XX` for every byte outside `A-Za-z0-9._-+@=,()`) and is flagged, files are created exclusively through directory descriptors (`O_EXCL`, `O_NOFOLLOW`), so a link planted in the output directory is not followed (the member goes under `_flat/`), and the directory is 0700 and the files 0600. Every member is a row of `members.jsonl` in archive order, numbered with the `n` the `archive-members` recipe gives it (a test compares them), with its exact name bytes (`name_b64`), type, declared and written sizes, times as stored with their zone said, flags, status (`extracted`, `partial`, `directory`, `not_created`, `encrypted`, `unsupported`, `skipped`, `failed`) and path; two members with one name are two files (`~dup2`); an encrypted member is counted and never opened; a name shaped like a token is withheld from every channel (the withholding block is the network pack's, byte for byte) and kept in `withheld-names.jsonl` (0600). A member is written as `<path>.partial` and takes its name only when its size and CRC match what the archive declared; the bytes of a member cut by a truncated archive, a CRC mismatch or a budget stay as `.partial` with the reason, including (for a damaged tar.gz) the bytes the decompressor had produced before the break; a digest or CRC of a member shorter than 128 bytes is not written. Budgets are `max_total_bytes`, `max_member_bytes`, `max_members`, `max_ratio` (default 1000; an archive that compresses further than that, such as a mostly empty disk image in xz, needs it raised on purpose), `max_depth` and `max_seconds`; a member-level budget skips or cuts that member and goes on, a global one stops the run and gives `next_index` (`from_index` with `resume: true` goes on in the same directory, refuses an archive other than the one the earlier run extracted, and writes `members.2.jsonl` beside the first). A nested archive is named (`looks_like`) and not opened: one call extracts one level. There is no name filter, which would answer questions about withheld text. A 7z archive goes through the `7z` program (`7z`, `7zz` or `7za`), whose output stream is split by its own listing and checked against the listing's CRC, so the program never writes a file; the program is started in the tool's own process group and ended on the tool's deadline and on SIGTERM, SIGINT and SIGHUP (the network pack's process block, byte for byte; a test kills the group the way the harness does and asks whether `7z` and what it started are dead). A 7z with encrypted headers cannot be listed and is refused; with some members encrypted it extracts the rest. zstd needs Python 3.14, the `zstandard` module or the base image's `zstd` program and is otherwise reported unsupported with that reason. The `archive-members` recipe now points at the tool for the member number and says a zstd tar is not listed by it (it never listed one; it said the extractor was planned), and `evidence/collections` describes the tool instead of saying the pack ships no extractor.

The tests are `packs/computer-forensics-base/tests/test_archive_extract.py` (52): archives built by the standard library with header bytes patched where it will not write what an archiver could (a NUL in a name, an encryption flag, an unknown compression method, an understated size), gzip, bzip2 and xz streams by their modules, and a 7z by the real program (those skip where none is installed), with the expected bytes the bytes that went in; `tests/pack-base-shared.test.ts` holds the withholding and process blocks equal to the network pack's. They ran on Python 3.12 and 3.14 on macOS and in Linux containers (Python 3.11 with 7-Zip 26.02, Python 3.12 with 7-Zip 23.01); the 7z tests also pass against p7zip 16.02 on Python 3.10, which is outside the supported range (an earlier `sqlite_query` test fails there because `Connection.setlimit` needs Python 3.11, as that tool says). Not done: RAR and other containers, recursion into nested archives, a local-header recovery of a zip whose central directory is gone (the error carries the count of local headers seen), and name filters.
