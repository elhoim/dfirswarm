### Changed: pack goal templates no longer require a number of ledger events

Each pack's goal template (the eleven packs on main that ship one: cloud-forensics, encrypted-containers, linux-forensics, macos-forensics, memory-forensics, mobile-forensics, network-forensics, ransomware-response, reverse-engineering, triage-collection, windows-forensics; fourteen templates in all) ended its checks with a line that counted `event` entries in the ledger against a minimum between 3 and 8. A run could satisfy the count and answer nothing, and a case with few dated events could be complete and still fail it. The line is gone from all fourteen. Completion is judged by the answer dispositions `scripts/check-answers.ts` reads (an answer on a finding, a partial one, a bounded negative, a question shown not determinable), which every goal still runs over each of its questions, the summary and the narrative. No other check was loosened.

- **ransomware-response** reads answer 2 for the exfiltration conclusion in one `awk` pass instead of `awk | grep -q`: on a long answer 2 the second command could leave first, the first received a closed pipe, and `set -o pipefail` failed a correct report.
- **memory-forensics** asks for network state as recovered endpoints and listeners, their supported owner associations, the method, and whether allocation state can be determined from the output used, instead of presuming the live-table-versus-freed split is exposed; its definition of done says that a limitation which names a defect lets the run end and leaves the defect counted, and does not fix it, and that evidence which is not there is stated as a supported partial, bounded-negative or not-determinable answer.
- `tests/pack-goals-checks.test.ts` reads every `packs/*/goals/*.md` and holds: no check counts events against a minimum, the other checks are all still there (report, one heading per question, the answers check over exactly the questions asked, the inputs check, the skill index), every check that reads the report passes a report of about 300 KB per answer under `set -euo pipefail` and reads only the answer it names. A goal template added by a later pack is held to the same rules.

The eleven packs above are re-sealed and their versions raised by a patch (the seal covers the goal templates). The goal of the virtualization pack (open pull request) is not on main and is not changed here; it must be checked against `tests/pack-goals-checks.test.ts` when that pack merges.
