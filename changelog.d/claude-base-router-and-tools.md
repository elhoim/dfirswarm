### Added: the base pack has a router, so a run that carries it with other packs stays inside the skills index budget

`computer-forensics-base` names `base/router` (at most 400 tokens) as its router. When a run's index is over its 2,500-token budget the prompt shows each router-bearing pack by its router's one line, and the router names every other base skill by the question it answers. The `disk` profile (base, encrypted-containers, windows-forensics) had 3,058 tokens of index entries and no pack to shorten; it now shows 2,194. Combinations that still pass the budget do so because windows-forensics, linux-forensics, memory-forensics and macos-forensics have no router: a pack with none is shown whole. Pack `computer-forensics-base`.

### Changed: the three base leaves over 800 tokens are split into second-level leaves

`filesystem/layers` (884 tokens) keeps the container, split-set and virtual-disk rules and hands the logical-volume and APFS rules to `filesystem/layers-mapping`; `timeline/clocks` (817) keeps epochs, zones and resolution and hands clock changes, drift, monotonic order and the two NTFS time sets to `timeline/clocks-drift`; `data/sqlite` (835) keeps the set, the snapshot and the query and hands secret tables to `data/sqlite-secrets`. Each parent says "only if" where it points. No rule sentence was removed: `tests/pack-split-rules/computer-forensics-base.json` registers the sentences of the three old leaves and `tests/pack-base-skills.test.ts` fails when one is gone. Every base leaf is now at most 800 tokens (the largest is 799.8), the pack index is 988 tokens of entries (limit 1,000), and every old skill id still resolves. Pack `computer-forensics-base`.

### Added: `sqlite_query` can write the values of a secret table to a sealed file

With `write_values: true`, in a job run with `secret_output: true`, the tool takes `table` (and optionally `columns`, `rowid_from`, `rowid_to`) instead of `sql`, writes every non-NULL cell to `sqlite-query-values.jsonl` under `$OUT` (mode 0600, created with `O_EXCL` and `O_NOFOLLOW` before any row is read, so a second run in the same job is refused as JSON and a link at the name is not followed) and puts none of them in the answer: the answer carries each cell's locator (table, `rowid`, column), type and length, per-column counts and the first rows, and `locators_file` has every row. No hash, digest or fragment of a value is written anywhere, and a database, table or column name shaped like a token is withheld from every printed channel (the network pack's withholding block, now also in this tool, byte for byte; the test that holds the copies equal covers it). There is no `sql` in this mode on purpose: a `WHERE` or `LIKE` over a column whose values are withheld would confirm a guess, one call at a time, so rows are chosen by `rowid` range, never by value. Outside a job the request is refused as JSON; the ordinary mode is unchanged. `data/sqlite-secrets` points secret tables to the mode and keeps the locator-column query as the fallback outside a job; `docs/packs.md` states the rule for every tool that takes a filter. The tool-library copy is updated with it. Pack `computer-forensics-base`.
