### Fixed: the mobile pack's filters and sealed files no longer answer questions about text nobody can see

`sqlite_freespace`, `manifest_db` and `protobuf_peek` withhold the text of a free page, the name of a backup file and the content of a protobuf field. Each of the following let a caller learn a withheld string one bit at a time, or printed some of its characters; they are closed, and the pack is 1.5.3.

- `sqlite_freespace` `contains` as a size and digest oracle: the values file held only the fragments the expression matched, and the harness shows a job's output size and digest to whoever asked for the job. The file was 299 bytes for the right prefix of a hidden token and 0 for a wrong one (62 calls recover a character). The file now holds a row for every fragment found, whatever the expression says; each row has `match` (1 matched or no expression, 0 did not, 2 could not be decided) and a random `run`, so its size does not depend on the expression and its digest differs in every run (ten expressions, right and wrong prefixes, one size). A reader of the file filters on `match`. The answer's `secret_values.written` is now the number of fragments, not of matches.
- `sqlite_freespace` `contains` as a timing oracle: it accepts only an expression of at most 256 steps (it was 16,384): no `*`, `+` or `{m,}`, no repeat of a choice, no lookahead, lookbehind or back reference, at most 256 characters. `\d(?:.?){10}Y` took 1.75 s on a hidden region of digits and 0.05 s on one of letters, and `Zq7K(?:.?){10}Y` was 90 times slower with the guess present; both are refused now. What is left is small, not zero: the slowest of 171 accepted candidate expressions (one class of characters repeated 250 times) took 0.06 s of CPU on 32,768 characters of that class against 1.1 s under the old bound, so the run time can still say that a long run of one class of characters exists in the free space. The manifest, the README and the skill say so.
- `sqlite_freespace` `contains` that ran out of time: a fragment it could not decide on was written to the values file as if it had matched while the answer said `complete` (`(?:a?){10}Z`, which matches nothing, wrote 27 of 39 rows), and the time the expression took did not count toward `max_seconds` (`max_seconds: 3` took 10.3 s). Such a fragment is marked `match: 2`, counted under `scanned.contains_not_decided` and `problems`, and the status is `partial`; the expression's time counts toward `max_seconds`, and the 10-second total allowance is gone.
- `protobuf_peek` counts: for a window that was not shown, the answer still printed `field_count`, `top_level_fields`, `counts` and, for a group, the status `unsupported`. The parse stops at the first error, so those numbers came from the bytes of a token as much as the rows would have: a window slid over a base62 token left 18 of 62 candidates for each character, a digit 3.4 of 10, and a 6-digit PIN lost about 8 of 20 bits. Every window that is not shown now gets the status `not_accepted` in the same words and zero counts. Its values file is one row of the size of the window (the whole window as hexadecimal and what the parser found, in a fixed width) instead of one row per field it parsed, and the readings of a number under a nested message are written in one width.
- Recovery-password names: only the dashed eight-by-six form was withheld from a path or a domain. A name is now withheld when it holds 42 or more decimal digits with at most three separator or invisible characters between two digits, after NFKC folding: spaces, underscores, dots, any dash, 48 contiguous digits, full-width and Arabic-Indic digits, a zero-width character inside, seven groups. On a seeded set, 14 shapes were withheld 40 times of 40 each, and 9 shapes that are not keys (uuids, hashes, timestamps, phone numbers, six groups of six digits) were printed 40 times of 40, in each of the three tools; a 32,768-character name of digits and separators costs at most 29 ms.
- `manifest_db` says `partial` when a listed row's `file` cell was not read (`too_large`) or could not be used (`malformed`), and lists `domains` by the text it prints, so a withheld domain no longer stands where its hidden name sorts. `file_id`, the SHA-1 of the domain and the real path, is still printed for a withheld path, as it is the blob's name in the backup directory and a listing of the directory shows the same digest; the manifest and the skill say so.
- The three tools write their answer in one piece: a stop signal that arrives while a large answer is written to a reader that has not read yet used to leave a truncated answer followed by the failure document; the signal is ignored once the answer is being written, and the reader gets one document. `[[:alpha:]]` and similar no longer print a `FutureWarning` to stderr.
- `protobuf_peek`'s residual outside the layout it was measured in is now stated: for a token that is the whole of one string field, 0 to 1.2 percent of tokens have a shown window; for a 32-character hexadecimal token split across two fields, 4.8 percent; for a 64-character one written as repeated six-byte pieces, 12.5 percent; for a 32-byte one, 8.1 percent; for a 64-character one inside a nested message, 3.9 percent (never a whole token).
- `packs/mobile-forensics/tests/pack.test.sh` ran the tools as a job without `SECRET_OUTPUT=1`, so `protobuf_peek` refused `write_values` and the shell-suite step failed; it sets the flag now.

The earlier fixes of this pack stand: `contains` and `domain` of `manifest_db` match the printed path and domain; a `file` cell is read only when it is a BLOB of at most 1 MiB (three rows holding a 29 MB archive took 399 MB of resident memory and now take 22 MB); a window that is entirely printable text is never shown and a window aimed with `offset` or `length` needs 16 bytes and four fields; `sqlite_freespace` and `protobuf_peek` declare `secret_output: {"when_args": ["write_values"]}` and refuse `write_values` in a job that was not run as secret output; all three answer SIGTERM, SIGINT and SIGHUP with one JSON document (`status: failed`, `interrupted`), exit 128 plus the signal, close and name the pages already written and remove the `manifest_db` working copy; all three say `status_basis`, and `protobuf_peek` says `status`; the manifest, skill and README say that the device identifiers in the plain plists (serial number, UDID, IMEI, ICCID, phone number) are printed.

### Fixed: the tool test helpers no longer crash on a child that never reads its input

`runPy`, `runSh` and `runPySnippet` wrote their JSON to a child's stdin with no error listener, so a fixture builder that exits without reading it (every `runPySnippet` call that passes `null`) could end the whole test file with `write EPIPE` on a loaded runner. The helpers ignore the error of a child that exited (`EPIPE` and `ERR_STREAM_DESTROYED`, and no other), and `null` now means no input at all.
