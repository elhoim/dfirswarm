### Changed: a live run's evidence, its ceilings and its operator, set before the rerun

The Breadcrumbs run (a Windows memory image, a capture and an AD1 image, nine seats, `--stop operator`) showed six places where the operator was not told, or could not act, in time. Each is closed at the kickoff, before anything is written, or told as it happens.

- **Writable evidence in a VM run is refused.** Used in place, evidence this account can write (a file, or a directory whose names can change, on a volume mounted read-write) is held by the VMs' read-only mount and nothing else. It was a warning; in the run a helper of the operator's own wrote a file into the live evidence folder, and the seats spent an hour telling an added name from a changed object. Now it is a BLOCKER under every stop policy and at `start --check`, naming both ways out: `--inputs-copy`, or `chmod -R a-w` / a read-only mount first. The usage, the quick start and the README make `--inputs-copy` the way to start a live run. A link out of the evidence is still refused first.
- **`--derived-limit N`** (and `SWARM_DERIVED_LIMIT`): the derived catalogue's ceiling of generations a run, 50 by default, recorded as `isolation.jobs.derived_limit` and said at kickoff with where it came from. The run reached the ceiling (52 against 50: it is checked before each pass, and a pass in flight finishes). Refused with `--no-derived-catalog` or without a job service.
- **`--token-alert N[,M…]`**: marks in tokens (`200M,400M,1.6G`) the operator is told of as the run crosses each, once each (claimed in `traces/token-alerts/`, across hub restarts and resumes): a `TOKEN ALERT` board post, a `token_alert` trace line, the notify hook's new `token_alert` event, and the console's Budget tab. Advisory under every stop policy; made for `--stop operator`, where the caps say nothing (the run spent 790 M tokens).
- **`--operator ID`**: an examiner or analyst enrolled on this install, named at kickoff (refused otherwise, at `--check` too) and recorded; on the run's acts (`question`, `resume --question`, `requests`) `--as operator` names them. The run's first resume asked its question `--as operator` with nobody enrolled under it, and the register refused it. A run that names none reads `--as operator` as before.
- **The model asked for, and the model that answered.** The registry keeps the ids asked for and the date (`model_identity`), and the kickoff warns of an id with `latest` in it. When a provider reports another model answering a seat (Pi's `responseModel`), the seat's harness puts `model_reported` on the trace; an alias resolved to a dated id is only recorded, any other model is a substitution, said on the board (`MODEL SUBSTITUTION`) and, through the hub, to the notify hook (`model_substitution`).
- **`start --check` warns of a required question the goal does not number**, as the start's seed already did (`questions-cli.ts goal-check`).
- **The report says which questions had to be established** (a `must be established` chip in the summary table, and a line under it: who required each and why, and each requirement released, by whom, when and why).

### Changed: whose credential each seat uses, and under which terms

From a review of the providers' published terms (2026-10-01; not legal advice), ADR 0003 "Whose credential, under which terms":

- **An `anthropic/*` seat on a Claude subscription login is refused in every run**, `--allow-oauth-in-vm` or not (an `oauth` entry in Pi's store, or `ANTHROPIC_OAUTH_TOKEN` where the store holds no key): Anthropic does not permit Free, Pro or Max credentials in a third-party client such as Pi. The refusal says why and how to log Pi in with an API key.
- **`--customer-case`**: API keys only. Every subscription seat is refused (`openai-codex/*` whatever the store says), as are `--allow-oauth-in-vm` and `--policy ctf`, and each provider's key needs its owner named with **`--key-owner [PROVIDER=]OWNER`**.
- **Every run records whose credential each seat used**: the registry's `credentials` (seat, model, provider, `api_key`, `oauth`, `local` or `other`, the owner when named) and the custody anchor, which custody puts in `models.credentials` and a line of its verdict. A subscription seat is recorded, and said at kickoff, as "consumer plan; not for customer data"; Codex's subscription stays usable for test and CTF runs.
