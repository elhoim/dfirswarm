### Added: the virtualization-backup-forensics pack, first part: three tools and the skills that name them

A thirteenth pack for the part of a case that sits above the guest: what the hypervisor's management records and VM configuration files say, whether a disk or snapshot chain is whole, what a backup system's catalogue, job record and retention setting show, and which recovery points survive. It reads exports and files offline; it never runs hypervisor or backup software, reads no guest content, reaches no live system, and says plainly which products it cannot read. It depends on `computer-forensics-base` (which declares `qemu-img` and Dissect as optional programs) and adds no program of its own. This change carries the pack, its three tools and one skill for each; the router, the method leaves, the recovery skills and the goal template follow in the next change.

- **`virtualization_inventory`** lists the VMs, disk files, snapshots and datastores that VMware `.vmx`, `.vmsd` and `vmInventory.xml`, libvirt domain, snapshot and pool XML, and Proxmox VM configurations and `storage.cfg` name, with the file and the line or XML element of each statement. Hyper-V, VirtualBox and OVF files are recognised and listed as unsupported. A disk is looked up only among the files given (`in_set: no` is a statement about the set), a hypervisor storage volume is listed and not looked up, and the keys that look like credentials (a console password, a cloud-init password, an SSH key, a user-data blob) are named with their line and the length of the value and never shown.
- **`snapshot_chain_check`** reads VMDK descriptors (text or embedded in a sparse extent), VHD, VHDX and QCOW2 headers and the disk names in `.vmx` and `.vmsd`, and reports each disk, parent edge, descriptor extent and chain with its identity check (VMDK CID, VHD unique id, VHDX parent linkage; QCOW2 records none of its backing file and says so). Markers (an unclean-close flag, a QCOW2 dirty bit, a VHDX log GUID, a leftover delta no snapshot or configuration names, a running disk that is a delta while the snapshot database lists none, a lock artefact, a sparse extent no descriptor names) are candidates with the observation beside them, never verdicts. A name inside a file is looked up among the files given and never opened. `qemu-img` runs only when asked (`qemu_img: auto` or `require`), once per image with the format fixed and never with `--backing-chain`, and its answer sits beside the native reading.
- **`backup_audit_normalise`** turns the Proxmox VE and Proxmox Backup Server task index and task logs, or a CSV, JSON Lines or XML export of any product read through a mapping the caller declares (which field is the time, the action, the result, the actor and the object, how the time is written, what each action means), into canonical events with their file, line or record and byte offset. A product with no fixtures here (Veeam, Commvault, Rubrik, Cohesity, Acronis, NetBackup, vCenter and others) is refused by name when asked for with `format: auto`, and no vendor layout is guessed. A time with no zone is not assumed to be UTC.
- **For all three:** standard library only; every answer carries `status` and `status_basis`; every list is paged and the whole is kept in a file the answer names; every limit is reported (files, depth, entries, snapshots, chain length, line length, XML elements and depth, distinct values, time); XML is read with every DOCTYPE and entity declaration refused; a name or value that looks like a token, a key or user-info is withheld by the block the network pack's tools carry, byte for byte, and the originals go to one 0600 file only with `write_text: true` in a job; in a job only `$OUT` is written.
- **Skills:** `hypervisor/inventory`, `snapshots/chain-integrity` and `backup/catalogues-and-retention`, each within the 800-token budget (the largest is 726).
- **Limits worth knowing.** The layouts are implemented from the formats' public descriptions and checked against synthetic files and, where a host has one, against files a real `qemu-img` made (qcow2, VMDK, VHD and VHDX, 7.2 here); VHD differencing disks and VHDX parent locators are checked against synthetic files only, because that `qemu-img` cannot make them. They have not been checked against files every product and version writes. Version and vendor facts are not stated.
- **Tests.** `tests/pack-virtualization-chain.test.ts`, `-inventory`, `-audit`, `-shared` (the shared blocks held equal to each other and to the network pack's withholding and process blocks, the manifests held to the scripts, only `$OUT` written in a job) and `-fuzz` (a seeded mutation fuzz, 120 mutants per tool by default; 3,200 per tool were run for this change), with the builders in `tests/pack-virtualization-harness.ts`, and the pack's own `tests/pack.test.sh`. `docs/packs.md` and `README.md` carry the pack's row.
