### Added: the exact Windows kernel symbol table in the memory image, made by the operator's build

A CTF run's Windows memory image had a kernel neither the Foundation's 2019 bundle nor JPCERT/CC's collection holds, so Volatility's Windows plugins could not read it in a worker with no network. The memory and `full` images now carry a curated set of exact kernel tables beside the bundle, each made from a PDB the operator fetched, with the operator's acceptance of Microsoft's terms recorded.

- **A curated list**, `packs/memory-forensics/requires/symbols.windows.json`: per kernel the PDB name, GUID and age, the PDB's sha256 and size, the converter version and the content hash its table must have. First entry: `ntkrnlmp.pdb` `D9424FC4861E47C10FAD1B35DEC6DCC8` age 1. Identifiers and hashes only; no Microsoft file is in the repository. `volatility3` is pinned at 2.28.2 in the memory and windows packs (the memory and windows packs).
- **`scripts/swarm.sh symbols fetch --accept-terms --accepted-by NAME [--from DIR]`** puts the PDBs into the host's store (`$DFIRSWARM_HOME/symbols/blobs/sha256/<sha256>`, refused in a synced folder) and records who accepted Microsoft's symbol-server terms, when, for which bytes, and how: whether a terminal was on both ends, the account, the host, the command (`manifest.json`, every earlier acceptance kept, each a line of `fetched.jsonl`); refused without the acceptance and a name, which nothing stands in for. A build takes an unattended acceptance (a process's) only with `--allow-unattended-acceptance`, prints the acceptance it bakes, and refuses a build context in a synced folder or a git checkout when it would hold a copy of the PDB. A download is HTTPS on every hop, redirected at most twice and only to the listed storage hosts, capped at the pinned size, within a time limit. `symbols list` shows what is held and accepted.
- **The build converts.** `install.data` gained `commands` and `outputs` (a source converted in the build, each output hashed and, with `canonical`, compared by content), `converter` (the version a content hash holds for), `acquire: "operator"` (never fetched by the build, taken from the store with its acceptance or the build stops before Docker), `set` and list files expanded from a template. A table's content is compared by **json-canon/1** (decompressed, duplicate keys and non-finite numbers refused, `metadata.producer.datetime` removed, sorted keys, ASCII, default separators), since its bytes change at every conversion. A curated table's check requires exactly one table with its identity in Volatility's listing, so the table read is the one recorded. `image.json` keeps source, transform, outputs and acceptance apart; each data entry is `distribution_policy: "local-only"`, its NOTICE lines name supplier, source, terms, derivation and restriction, and the image's label `dev.dfirswarm.data` names what it carries.
- **`recipe.py build --symbol-set curated|broad|none`** (default `curated,broad`); a set left out is recorded under `omitted.data`, apart from a failure, and a kickoff says so. CI builds with `none` on a pull request and `broad` weekly: it never fetches a Microsoft PDB and never builds the curated set.
- **A local data mirror**: `--data-from DIR` / `DFIRSWARM_DATA_DIR` (and `--symbols-from`, the store) hand the build local copies by sha256, bound into the install step rather than copied into a layer, so a rebuild does not download the 840 MB bundle again.
- **Every download is bounded**: HTTPS on every redirect hop, the pinned size (`bytes`, now required of every data entry) or a cap, an overall time limit.
- **A missing table stops the start.** The base pack's `memory-windows` recipe, whose detect already asks Volatility offline about each memory input, now names the kernel (PDB, GUID, age) whose table the image lacks, and says when its probe did not answer in time (then whether the table is held is unknown, and the start does not go on blind). The census writes what a recipe says is missing to `catalog/missing.json` and its README, a generation's post says it, and with `--catalog` a missing symbol table is a BLOCKER at `start --check` (the census's detect in a throwaway VM) and at the start, unless `--allow-missing-symbols`.
- Docs: `images/README.md` ("Symbol tables"), the memory pack's README and `triage/volatility` skill, `docs/usage.md`, an addendum to ADR 0010. Microsoft's terms grant use for debugging and testing your software; whether examining a third party's memory image falls inside that is not decided here.
