# Improvement plan after the first forensic run

Written after run `s2cb9` (seven agents, a 26 GB forensic case, 14.5
minutes, $7.98 — [the use case](use-cases/dfir-web-server-case/README.md)).
Part A is what the run showed about the harness itself; part B is what a
swarm built for digital forensics and incident response needs beyond that.
Each item says what was observed, what changes, and how it is verified. The
status column is updated as items land.

## How run 2 is judged

The same case, the same team and cap, `--catalog --toolbox auto --quarantine
--seats dfir --cap-per-agent 12 --allow-host isf-server.techanarchy.net`
with netguard on. What should change against run 1: shell-write notices
only for real conflicts (was 40), no idle agent at the end (was 3), seats
taken as assigned (was two minutes of negotiation), a timeline built through
`record` (was a thread of handoffs), no agent rebuilding the file list (was
three), more than one forged tool or the hint on the board (was one), and a
package at the end. Cost and wall time are reported, not targeted.

**Verdict (2026-09-18).** Run 2 (`sf6df`) met five of the seven and found
six defects in the new code (A11, A12, the own-scratch guard, the console's
"dead" count); run 3 (`sf4b2`), on the harness with those fixed, met all
seven: 1 notice (a real stomp) against 40, 0 idle agents at the end, seats
taken without negotiation, a ledger of 69 entries by every seat feeding the
timeline, 0 rebuilds of the file list, 2 forged tools (one used by a peer),
and `swarm.sh package` at the end. Cost went from $7.98 to $12.45 and time
from 14.5 to 17.9 minutes. The comparison is in
[docs/use-cases/dfir-web-server-case/run-2.md](use-cases/dfir-web-server-case/run-2.md).
The next observed need: nudged agents end their turn instead of holding
`wait`, so the watchdog fires every three minutes (A13, below).
