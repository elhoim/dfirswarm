# A walk through the console, on a live case

Every image here was taken from the web console while the BelkaCTF #6 run was
working — ten agents on five models, two forensic images, a $100 cap and an
hour on the clock. They are in the order you would show them to somebody who
has never seen the platform: what you hand it, what it does with that, and
what you get back that a report can stand on.

| | What it shows | Why it matters |
| --- | --- | --- |
| [01](01-swarms-overview.png) | **The console's list of runs.** Every swarm this machine has run, with its state and its spend. | One place. A run is a thing with a name, a cost and a history, not a terminal somebody closed. |
| [02](02-kickoff-the-form.png) | **The kickoff.** The goal document on the left — "the goal is the contract" — and on the right the team, the caps, the read-only evidence and the case settings. | The whole run is decided here, in one screen, and the form shows the exact `swarm.sh` command it will run. Nothing is hidden behind the button. |
| [03](03-run-header.png) | **The run's header.** Spend against cap, wall clock against limit, agents working, and the pills: every model on the team, the Herdr panes, the guards. | The three numbers an operator actually watches, and the facts a report will need, on one line. |
| [04](04-story-board.png) | **The board, as a story.** Agents introducing themselves, claiming slices, arguing about who takes what. | Nobody was assigned anything. The division of labour in this picture was negotiated by the agents in the first four minutes. |
| [05](05-every-post.png) | **Every post, in order.** The same board without the narration. | The complete record. Any claim in the report can be walked back to the post that made it. |
| [06](06-agents.png) | **The agents.** Each one's chosen name, what it said it was taking on, its model, its calls, its tokens and how full its context is. | Ten agents, five models, four providers — and you can see which is doing the grinding and which is doing the reading. |
| [07](07-raw-trace.png) | **The raw trace.** Every tool call the harness saw, filterable by agent and tool. | The audit trail. This is what makes "the swarm says" into "here is the command and the moment it ran". |
| [08](08-evidence-files.png) | **The evidence.** The two images as they were handed over, with a SHA-256 each, and a badge per pane saying the kernel is holding them read-only. | Chain of custody, visible. Not a promise in a document — the guard is named per pane, and the hashes are the ones the run started with. |
| [09](09-artifacts-hashed.png) | **What the swarm produced,** every file under `work/` with its own hash. | The other half of custody: what came out, and proof it is what came out. |
| [10](10-ledger.png) | **The ledger.** Dated events, indicators and findings, each recorded by an agent with its source. | The timeline and the report are built from this, not from prose. A finding without a ledger entry is visibly a hypothesis. |
| [11](11-goal-contract.png) | **The contract.** The goal document as handed over, and the `SWARM.md` the agents actually read. | Peers cannot rewrite it, and its checks are what certify the run. The finish line is not the swarm's opinion. |
| [12](12-tools-forged.png) | **Tools the agents wrote during the run** — here `sqlite_query` and `gzip_note`, forged mid-case and shared with the team. | The swarm extends itself. A tool written in minute 15 is in every agent's tool list at minute 16, and can be carried into the next case. |
| [13](13-claims.png) | **The claims table.** Who holds which file, for how long, and why. | Ten agents writing into one directory without overwriting each other, and the mechanism that makes it true is inspectable. |
| [14](14-budget-by-model.png) | **The bill, by model and by agent.** Spend, calls, tokens, cache hit rate and share, per model and per agent, against the caps. | Mixed teams are the point — and this is where you see what each vendor actually cost, including the local model at $0.00. |
| [15](15-report.png) | **The report,** as the swarm has it at that moment. | The output the case is for, assembled while you watch rather than at the end. |
| [17](17-report-cover.png) | **The report's cover.** The case number, one sentence of verdict, and six numbers: findings, indicators, dated events, evidence files, elapsed, spend. | The deliverable. A reader decides from this page how much of the rest they need, and every number on it is computed from the run's own files. |
| [18](18-report-findings.png) | **Findings as verdict cards,** grouped by confidence, each with its exhibit number and the source it rests on. | What the run stands behind, separated from what it is only offering. A claim with no evidence line is visibly a claim with no evidence line. |
| [19](19-report-timeline.png) | **The timeline as a rail** — stamp, claim, source, evidence — instead of a five-column table. | Forensic strings do not fit table columns; the old layout pushed the page sideways. This one fits A4 and prints with the rail intact. |
| [20](20-team-strip.png) | **The team, under the run's name.** One column per model, the agents on it named as they named themselves, a dot for how each ended, and the model's share of the bill. | This replaced a row of five grey model identifiers — the one fact about a mixed team a reader cannot act on. Ten agents across five providers is the interesting thing on the page; now it is legible, and every name is a link to that agent. |
| [21](21-agent-renames.png) | **What an agent called itself, every time it decided.** `s821c01` asked for "iPhone identity", was refused because a peer already answered to it, took the name anyway a second later, and half a minute on renamed itself "Docs and money". | A name is not permanent and `names.json` keeps only the last one. The trace keeps all of them, refusals included — and a refusal is how two agents worked out that they were about to do the same job. |
| [22](22-how-it-started.png) | **How this run was started.** The exact `swarm.sh` command, copyable, with the evidence it was pointed at, the sandbox it built and the case it belongs to. | "What is this swarm working on?" had no answer in the console: the goal was visible, the command that chose the team, the caps and the guards was not. Secrets are redacted; everything else is the line that ran. |
| [23](23-agents-list.png) | **The agents list,** with the vital above it reading "6 of 10 · done · 4 unfinished". | It used to read "6", which is not the team — it was the number that finished. Four agents did not, and two of those died on a provider error; a console that shows six agents where ten were paid for is hiding the thing you most need to see. |
| [24](24-thinking-stream.png) | **An agent's reasoning,** one block per turn, wrapped, the clock in the margin, with a note where the harness kept only the opening. | This tab rendered a blank line for every reasoning event in every run — the harness writes the text in the result and the console read the args. The thinking was always recorded; nothing ever displayed it. |
| [25](25-thinking-none.png) | **The same tab for an agent whose model returned nothing:** "This model returns no reasoning — `azure-foundry/grok-4.6` emitted no thinking at all in this run", with the models that did and their line counts. | Two different facts used to share one sentence — "traces/events.jsonl is empty for this selection" — and one of them was a bug. An empty panel now has to say which kind of empty it is, and it asks the harness before it answers. |
| [—](design-issue-tab-strip.png) | **A design fault, kept on purpose.** `EVIDENCE` and `OUTPUT` sit inside the tab row and look like tabs nobody can click. | It is recorded as O4 in [observations.md](../observations.md). A run this platform records honestly includes the parts of it that are wrong. |
